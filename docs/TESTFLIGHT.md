# Как выложить «Деберц» в публичный TestFlight

Итог: у вас будет ссылка вида `https://testflight.apple.com/join/XXXXXXXX`. Папа и друзья открывают её на iPhone или iPad, ставят приложение через TestFlight и играют. Mac для этого не обязателен: сборку и загрузку делает GitHub Actions.

Всё, что касается самого приложения, уже подготовлено:

- иконка 1024×1024 без прозрачности;
- поддержка iPhone и iPad; на iPad работают все ориентации экрана, как требует многозадачность;
- в сборке указано, что шифрование не используется (`ITSAppUsesNonExemptEncryption = NO`), поэтому вопросов об экспорте не будет;
- есть манифест приватности `PrivacyInfo.xcprivacy`: данные не собираются, трекинга нет, `UserDefaults` используется только для своих настроек;
- сборка идёт на Xcode 26 с iOS 26 SDK — это требование Apple с 28 апреля 2026 года;
- workflow `.github/workflows/testflight.yml` собирает архив, подписывает его и загружает в App Store Connect.

Вам остаётся настроить аккаунт Apple и выполнить шаги ниже. Первый раз это займёт около часа, не считая ожидания Apple.

---

## Шаг 1. Apple Developer Program

1. Зайдите на [developer.apple.com/programs](https://developer.apple.com/programs/) и оформите членство как частное лицо (Individual). Стоит $99 в год.
2. Дождитесь подтверждения. Обычно это от нескольких часов до двух суток.
3. Узнайте свой **Team ID**: [developer.apple.com/account](https://developer.apple.com/account) → раздел **Membership details** → **Team ID**. Это 10 символов, например `A1B2C3D4E5`.

## Шаг 2. Идентификатор приложения (Bundle ID)

В проекте указан `com.islam2412.deberc` (файл `Config/Deberc.xcconfig`).

1. Откройте [Certificates, Identifiers & Profiles → Identifiers](https://developer.apple.com/account/resources/identifiers/list) и нажмите **+**.
2. Выберите **App IDs** → **App** → **Continue**.
3. Заполните поля:
   - Description: `Deberc`;
   - Bundle ID: **Explicit**, `com.islam2412.deberc`.
4. Отмечать какие-либо возможности (Capabilities) не нужно. Нажмите **Continue** → **Register**.

> Если такой Bundle ID уже занят, придумайте свой, например `com.<ваша-фамилия>.deberc`. Затем либо впишите его в `Config/Deberc.xcconfig`, либо заведите в GitHub переменную `BUNDLE_ID` (см. шаг 5).

### Желательно: зарегистрировать свой iPhone

Workflow сначала пробует стандартный путь Apple — архив с подписью разработчика. Для этого в команде должно быть хотя бы одно зарегистрированное устройство. Если устройств нет, workflow сам переключится на запасной путь, но стандартный надёжнее. Зарегистрировать устройство можно двумя способами:

- **Если есть Mac:** откройте проект в Xcode, подключите iPhone кабелем и один раз запустите приложение на нём. Xcode зарегистрирует устройство сам.
- **Без Mac:** [Devices → +](https://developer.apple.com/account/resources/devices/add), имя — любое, UDID — идентификатор iPhone. Его показывает Finder или iTunes, если подключить телефон к компьютеру.

## Шаг 3. Приложение в App Store Connect

1. Откройте [appstoreconnect.apple.com](https://appstoreconnect.apple.com) → **Приложения** → **+** → **Новое приложение**.
2. Заполните поля:
   - Платформы: **iOS**;
   - Название: `Деберц: наши правила`. Имя должно быть уникальным во всём App Store; варианты на случай, если это занято, — в [APP_STORE_CONNECT.md](APP_STORE_CONNECT.md);
   - Основной язык: **Русский**;
   - Bundle ID: тот, что вы зарегистрировали на шаге 2;
   - SKU: `deberc-001` (любая строка для себя);
   - Доступ пользователей: **Полный доступ**.
3. Нажмите **Создать**.

## Шаг 4. Ключ App Store Connect API

Через этот ключ GitHub Actions сам подписывает сборку и загружает её в TestFlight.

1. App Store Connect → **Пользователи и доступ** → **Интеграции** → **App Store Connect API** → **Ключи команды** → **+**.
2. Укажите:
   - Название: `GitHub Actions`;
   - Доступ: **Admin**. Права администратора нужны, чтобы Xcode мог сам создать сертификат и профиль для раздачи.
3. Нажмите **Создать** и сразу **Загрузить ключ API**. Файл `AuthKey_XXXXXXXXXX.p8` можно скачать **только один раз** — сохраните его в надёжном месте.
4. Запишите два значения со страницы ключей:
   - **Key ID** — в строке ключа;
   - **Issuer ID** — вверху страницы, над таблицей.

## Шаг 5. Секреты GitHub

Откройте репозиторий на GitHub → **Settings** → **Secrets and variables** → **Actions** → вкладка **Secrets** → **New repository secret**. Добавьте четыре секрета:

| Имя | Значение |
|---|---|
| `APPLE_TEAM_ID` | Team ID из шага 1 |
| `ASC_KEY_ID` | Key ID из шага 4 |
| `ASC_ISSUER_ID` | Issuer ID из шага 4 |
| `ASC_KEY_P8` | всё содержимое файла `.p8`, включая строки `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----` |

Если Bundle ID отличается от `com.islam2412.deberc`, на вкладке **Variables** добавьте переменную `BUNDLE_ID` с вашим значением.

> Секреты зашифрованы: их не видно ни в коде, ни в логах, и они недоступны форкам репозитория.

## Шаг 6. Сборка и загрузка

1. Если код ещё не слит в `main`, влейте ветку с приложением в `main` (или запускайте workflow прямо с этой ветки).
2. GitHub → **Actions** → **TestFlight** → **Run workflow** → выберите ветку → **Run workflow**.
3. Через 10–20 минут workflow завершится зелёной галочкой. Номер сборки — это номер запуска плюс 100: 101, 102 и так далее.
4. Ещё через 10–30 минут Apple обработает сборку, и она появится в App Store Connect → ваше приложение → **TestFlight**.

Загрузку можно запустить и тегом: `git tag v1.0 && git push origin v1.0`.

## Шаг 7. Публичный TestFlight

Этот шаг делается один раз. Для следующих сборок достаточно выбрать новую сборку в группе.

1. App Store Connect → приложение → **TestFlight** → **Информация о тестировании** (Test Information). Заполните поля; готовые тексты есть в [APP_STORE_CONNECT.md](APP_STORE_CONNECT.md):
   - описание бета-версии;
   - email для отзывов;
   - ссылка на политику конфиденциальности — `https://github.com/islam2412/deberc/blob/main/PRIVACY.md`;
   - контакты для проверки (Beta App Review Information): имя, телефон, email. Галочку «Требуется вход» **не** ставить.
2. Слева в разделе **Внешнее тестирование** нажмите **+** и создайте группу, например `Семья и друзья`.
3. В группе нажмите **+** у раздела «Сборки», выберите загруженную сборку, заполните «Что тестировать» и нажмите **Отправить на проверку** (Submit for Review).
4. Проверка Beta App Review обычно занимает до суток.
5. После одобрения в группе появится кнопка **Включить общедоступную ссылку** (Enable Public Link). Нажмите её, при желании ограничьте число тестировщиков и скопируйте ссылку.

## Шаг 8. Установка у папы и друзей

1. На iPhone или iPad поставьте приложение **TestFlight** из App Store.
2. Откройте общедоступную ссылку и нажмите **Принять** → **Установить**.
3. Когда выходит новая сборка, TestFlight предлагает обновиться. Можно включить автообновление.

> Каждая сборка в TestFlight работает 90 дней. Чтобы игра не «протухла», раз в 2–3 месяца запускайте workflow заново.

## Обновления

- **Исправления в той же версии (1.0).** Запустите workflow TestFlight. Новые сборки той же версии обычно проходят без полной проверки.
- **Новая версия (1.1).** Поменяйте `MARKETING_VERSION` в `Config/Deberc.xcconfig`. Первая сборка новой версии снова проходит Beta App Review.

## Если есть Mac: загрузка без GitHub Actions

1. Откройте `Deberc.xcodeproj` в Xcode 26+ → **Signing & Capabilities** → выберите свою команду (Team).
2. В `Config/Deberc.xcconfig` увеличьте `CURRENT_PROJECT_VERSION`: номер должен быть больше всех уже загруженных.
3. Выберите устройство **Any iOS Device** → **Product** → **Archive**.
4. В окне Organizer: **Distribute App** → **TestFlight & App Store** → **Distribute**.

## Частые ошибки

| Ошибка | Что делать |
|---|---|
| `Не задан секрет …` | Проверьте шаг 5: имена секретов должны совпадать буква в букву. |
| `No suitable application records were found` | Приложение не создано в App Store Connect (шаг 3) или Bundle ID не совпадает. |
| `Cloud signing permission error` / ошибка сертификата | У ключа API должен быть доступ **Admin** (шаг 4). |
| `You do not have required contracts` | App Store Connect → **Бизнес** → примите соглашения. |
| `The bundle version must be higher…` | Запустите workflow ещё раз: номер сборки вырастет. |
| `SDK version issue` | Сборка должна идти на Xcode 26+. Workflow использует `macos-26`, где он уже установлен. |
