# Как выложить «Деберц» в публичный TestFlight

Итог: у вас будет ссылка вида `https://testflight.apple.com/join/XXXXXXXX`. Папа и друзья открывают её на iPhone или iPad, ставят приложение через TestFlight и играют. Mac не нужен: сборку, загрузку и раздачу делает GitHub Actions.

Что уже подготовлено в самом приложении:

- иконка 1024×1024 без прозрачности, плюс тёмный и тонированный варианты для iOS 18 и новее;
- экран запуска цвета сукна, без чёрной вспышки;
- iPhone и iPad; на iPad работают все ориентации экрана, как требует многозадачность;
- минимальная версия — **iOS 16.4**: подходят iPhone 8 и новее (см. «Какие устройства поддерживаются»);
- в сборке указано, что шифрование не используется (`ITSAppUsesNonExemptEncryption = NO`), поэтому вопросов об экспорте не будет;
- манифест приватности `PrivacyInfo.xcprivacy`: данные не собираются, трекинга нет;
- сборка идёт на Xcode 26 с iOS 26 SDK — это требование Apple с 28 апреля 2026 года;
- workflow `.github/workflows/testflight.yml` собирает архив, подписывает его, загружает в App Store Connect, а потом сам вписывает «Что тестировать», добавляет сборку в группу и отправляет её на проверку.

Вам остаётся один раз настроить аккаунт Apple по шагам ниже. В первый раз это займёт около часа, не считая ожидания Apple. Потом каждая новая сборка выходит одним нажатием или одним тегом.

---

## Шаг 0. Ветка `main`

Основная ветка — `main` (ветка по умолчанию с 28.09.2026). Кнопка **Run workflow** есть только у тех workflow, которые лежат в ветке по умолчанию, поэтому запускайте их с `main`.

> Ссылку на политику конфиденциальности для App Store Connect берите такую: `https://github.com/islam2412/deberc/blob/HEAD/PRIVACY.md`. `HEAD` — это ветка по умолчанию. Репозиторий должен оставаться публичным, иначе Apple не откроет ссылку.

## Шаг 1. Apple Developer Program

1. Зайдите на [developer.apple.com/programs](https://developer.apple.com/programs/) и оформите членство как частное лицо (Individual). Стоит $99 в год.
2. Дождитесь подтверждения. Обычно это от нескольких часов до двух суток.
3. Узнайте свой **Team ID**: [developer.apple.com/account](https://developer.apple.com/account) → раздел **Membership details** → **Team ID**. Это 10 символов, например `A1B2C3D4E5`.

## Шаг 2. Идентификатор приложения (Bundle ID)

В проекте указан `com.islam2412.deberc` (файл `Config/Deberc.xcconfig`).

1. Откройте [Certificates, Identifiers & Profiles → Identifiers](https://developer.apple.com/account/resources/identifiers/list) и нажмите **+**.
2. Выберите **App IDs** → **App** → **Continue**.
3. Заполните поля:
   - Description: `Deberc`;
   - Bundle ID: **Explicit**, `com.islam2412.deberc`.
4. Отмечать возможности (Capabilities) не нужно. Нажмите **Continue** → **Register**.

> Если такой Bundle ID уже занят, придумайте свой, например `com.<ваша-фамилия>.deberc`. Затем впишите его в `Config/Deberc.xcconfig` или заведите в GitHub переменную `BUNDLE_ID` (шаг 5).

Регистрировать свой iPhone в команде не нужно: по умолчанию workflow собирает архив без подписи разработчика, а подпись для App Store ставит при экспорте.

## Шаг 3. Приложение в App Store Connect

1. Откройте [appstoreconnect.apple.com](https://appstoreconnect.apple.com) → **Приложения** → **+** → **Новое приложение**.
2. Заполните поля:
   - Платформы: **iOS**;
   - Название: `Деберц: наши правила`. Имя должно быть уникальным во всём App Store; запасные варианты — в [APP_STORE_CONNECT.md](APP_STORE_CONNECT.md);
   - Основной язык: **Русский**;
   - Bundle ID: тот, что вы зарегистрировали на шаге 2;
   - SKU: `deberc-001` (любая строка для себя);
   - Доступ пользователей: **Полный доступ**.
3. Нажмите **Создать**.
4. **Mac и Vision Pro — выключите.** По умолчанию Apple предлагает приложения для iPhone и iPad ещё и на Mac с Apple silicon и на Apple Vision Pro. Там окно меняет размер как угодно, вибрации нет, и игру там никто не проверял. Откройте приложение → **Цены и доступность** (Pricing and Availability) и снимите обе галочки: «Приложения для iPhone и iPad на компьютерах Mac с Apple silicon» и «Apple Vision Pro». Нажмите **Сохранить**. Если в разделе **TestFlight** есть переключатель тестирования на Mac, его тоже выключите. В самом проекте запуск на Mac и Vision Pro уже отключён.

## Шаг 4. Ключ App Store Connect API

Через этот ключ GitHub Actions подписывает сборку, загружает её и раздаёт тестировщикам.

1. App Store Connect → **Пользователи и доступ** → **Интеграции** → **App Store Connect API** → **Ключи команды** → **+**.
2. Укажите:
   - Название: `GitHub Actions`;
   - Доступ: **Admin**. Права администратора нужны, чтобы Apple могла подписать сборку сертификатом для раздачи прямо при экспорте (облачная подпись).
3. Нажмите **Создать** и сразу **Загрузить ключ API**. Файл `AuthKey_XXXXXXXXXX.p8` можно скачать **только один раз**, сохраните его в надёжном месте.
4. Запишите два значения со страницы ключей:
   - **Key ID** — в строке ключа;
   - **Issuer ID** — вверху страницы, над таблицей.

## Шаг 5. Секреты и переменные GitHub

Откройте репозиторий на GitHub → **Settings** → **Secrets and variables** → **Actions**.

На вкладке **Secrets** нажмите **New repository secret** и добавьте четыре секрета:

| Имя | Значение |
|---|---|
| `APPLE_TEAM_ID` | Team ID из шага 1 |
| `ASC_KEY_ID` | Key ID из шага 4 |
| `ASC_ISSUER_ID` | Issuer ID из шага 4 |
| `ASC_KEY_P8` | всё содержимое файла `.p8` вместе со строками `-----BEGIN PRIVATE KEY-----` и `-----END PRIVATE KEY-----` |

На вкладке **Variables** (переменные видны в логах, секретного в них нет):

| Имя | Значение | Когда нужна |
|---|---|---|
| `TESTFLIGHT_GROUP` | имя внешней группы, например `Семья и друзья` | после шага 7: тогда каждая новая сборка сама попадает к папе |
| `BUNDLE_ID` | ваш Bundle ID | только если он отличается от `com.islam2412.deberc` |

> Секреты зашифрованы: их не видно ни в коде, ни в логах, и они недоступны форкам. Workflow передаёт их только тем шагам, которым они нужны, а файл ключа удаляет в конце.

## Шаг 6. Пробный прогон и первая загрузка

1. GitHub → **Actions** → **TestFlight** → **Run workflow**. Ветка — ветка по умолчанию (шаг 0).
2. В первый раз поставьте галочку **Пробный прогон** (dry_run) и нажмите **Run workflow**. Workflow проверит секреты и ключ, найдёт приложение в App Store Connect, соберёт и подпишет `.ipa`, но ничего не загрузит. Так проблемы с подписью видны сразу, а не после настоящей загрузки. Готовый `.ipa` лежит в артефакте `Deberc-ipa`.
3. Если пробный прогон зелёный, запустите workflow ещё раз, уже без галочки. Через 10–20 минут сборка загрузится.
4. Номер сборки — дата и время сборки по UTC: `260927.1805` значит 27.09.2026, 18:05. Он всегда больше предыдущего, даже если перезапустить упавший workflow. Этот же номер виден в приложении: **Настройки** → внизу.
5. Задача **Раздача в TestFlight** ждёт, пока Apple обработает сборку (обычно 10–30 минут), и вписывает «Что тестировать». Если Apple сборку не приняла, задача станет красной и покажет причину.

Запустить можно и тегом. Версия берётся из имени тега, а сообщение тега становится текстом «Что тестировать»:

```sh
git tag -a v1.1 -m "Новые соперники и крупные карты"
git push origin v1.1
```

Тег проверяет, что CI этого коммита зелёный: на коммит с красным CI загрузка не пойдёт.

Параметры **Run workflow**:

| Параметр | Что делает |
|---|---|
| `signing` | `unsigned` (по умолчанию) — архив без подписи, подпись Apple Distribution ставится при экспорте. `auto` — сначала архив с подписью разработчика (нужен зарегистрированный iPhone в команде), а при ошибке подписи — как `unsigned` |
| `dry_run` | пробный прогон: `.ipa` в артефактах, без загрузки |
| `whats_new` | «Что тестировать» для этой сборки; пусто — текст из `docs/WHATS_NEW.txt` |
| `group` | внешняя группа; пусто — переменная `TESTFLIGHT_GROUP` |
| `submit_review` | отправить сборку на проверку Beta App Review |

## Шаг 7. Публичный TestFlight

Этот шаг делается один раз.

1. App Store Connect → приложение → **TestFlight** → **Информация о тестировании** (Test Information). Заполните поля, готовые тексты — в [APP_STORE_CONNECT.md](APP_STORE_CONNECT.md):
   - описание бета-версии;
   - email для отзывов;
   - ссылка на политику конфиденциальности — `https://github.com/islam2412/deberc/blob/HEAD/PRIVACY.md`. **Откройте её в браузере в режиме инкогнито** и убедитесь, что страница открывается без входа в GitHub;
   - контакты для проверки (Beta App Review Information): имя, телефон, email. Галочку «Требуется вход» **не** ставить.
2. Слева в разделе **Внешнее тестирование** нажмите **+** и создайте группу, например `Семья и друзья`.
3. В GitHub заведите переменную `TESTFLIGHT_GROUP` с точно таким же именем группы (шаг 5) и запустите workflow TestFlight ещё раз. Задача «Раздача в TestFlight» сама добавит сборку в группу и отправит её на проверку.
   Без переменной всё то же можно сделать руками: в группе нажмите **+** у раздела «Сборки», выберите сборку, заполните «Что тестировать» и нажмите **Отправить на проверку** (Submit for Review).
4. Проверка Beta App Review обычно занимает до суток.
5. После одобрения в группе появится кнопка **Включить общедоступную ссылку** (Enable Public Link). Нажмите её, при желании ограничьте число тестировщиков и скопируйте ссылку. Дальше workflow будет печатать эту ссылку в итогах каждого запуска.

## Шаг 8. Установка у папы и друзей

1. На iPhone или iPad поставьте приложение **TestFlight** из App Store.
2. Откройте общедоступную ссылку и нажмите **Принять** → **Установить**.
3. Когда выходит новая сборка, TestFlight предлагает обновиться. Можно включить автообновление.

## Какие устройства поддерживаются

Нужна iOS или iPadOS **16.4 или новее**:

- iPhone 8, 8 Plus, X и все более новые, включая iPhone SE 2-го и 3-го поколения;
- iPad 5-го поколения и новее, iPad mini 5 и новее, iPad Air 3 и новее, все iPad Pro.

На iPhone 7, iPhone 6s и более старых игра не установится: для них последняя iOS — 15. Перед тем как рассылать ссылку, узнайте модели телефонов у папы и друзей: **Настройки** → **Основные** → **Об этом устройстве**. Если iOS ниже 16.4, но телефон её поддерживает, достаточно обновиться.

## Обновления

- **Исправления в той же версии.** Запустите workflow TestFlight или поставьте тег. Если задана переменная `TESTFLIGHT_GROUP`, новая сборка сама попадёт в группу. Следующие сборки той же версии обычно проходят проверку быстро или без неё.
  Пока сборка ждёт первой проверки, **не загружайте и не отправляйте новую**: проверки ждёт только одна сборка приложения, и App Store Connect молча снимает с очереди прежнюю — даже если у новой другая версия (проверено: 1.0 сняли, когда на проверку ушла 1.0.1). Очередь для новой сборки начинается заново.
- **Новая версия (1.1).** Поставьте тег `v1.1`, версия возьмётся из него. При ручном запуске поменяйте `MARKETING_VERSION` в `Config/Deberc.xcconfig`. Первая сборка новой версии снова проходит Beta App Review.

### Срок 90 дней

Каждая сборка в TestFlight работает 90 дней. За несколько дней до срока TestFlight сам напоминает тестировщикам. Чтобы игра не «протухла», выпускайте новую сборку хотя бы раз в два месяца: запустите workflow или поставьте тег. Расписание (cron) тут не поможет: в публичном репозитории GitHub отключает его после 60 дней без коммитов.

## Если есть Mac: загрузка без GitHub Actions

1. Откройте `Deberc.xcodeproj` в Xcode 26+ → **Signing & Capabilities** → выберите свою команду (Team).
2. В `Config/Deberc.xcconfig` поставьте `CURRENT_PROJECT_VERSION` больше всех уже загруженных. Удобнее в том же формате, что и workflow: `ГГММДД.ЧЧММ` по UTC, например `260927.1805`.
3. Выберите устройство **Any iOS Device** → **Product** → **Archive**.
4. В окне Organizer: **Distribute App** → **TestFlight & App Store** → **Distribute**.

## Частые ошибки

| Сообщение | Что делать |
|---|---|
| `Не задан секрет …` или `… — 10 заглавных латинских букв и цифр` | Проверьте шаг 5: имена секретов должны совпадать буква в букву, значения — без пробелов. |
| `ASC_KEY_P8 должен содержать весь файл .p8…` | Вставьте в секрет весь файл, вместе со строками `BEGIN` и `END`. |
| `App Store Connect … → 401` | Ключ не принят: перепутаны Key ID и Issuer ID, или ключ отозван. Создайте новый (шаг 4). |
| `В App Store Connect нет приложения с Bundle ID …` / `No suitable application records were found` | Приложение не создано (шаг 3), или Bundle ID не совпадает с `Config/Deberc.xcconfig` и переменной `BUNDLE_ID`. |
| `Cloud signing permission error` / ошибка сертификата | У ключа API должен быть доступ **Admin** (шаг 4). |
| `No Team Found in Archive` | Неверный `APPLE_TEAM_ID`. |
| `You do not have required contracts` | App Store Connect → **Бизнес** → примите соглашения. |
| `::warning::Подпись разработчика не получилась…` | Так и должно быть при `signing = auto` без зарегистрированных устройств: workflow переходит на сборку без подписи. |
| `Номер сборки … не больше уже загруженного` | Вручную загрузили сборку с бо́льшим номером. Workflow берёт номер из даты и времени, поэтому ручные номера давайте в том же формате (раздел «Если есть Mac»). |
| `The bundle version must be higher…` | То же: номер должен расти. Workflow сам берёт дату и время, так что обычно достаточно запустить ещё раз. |
| `CI этого коммита не зелёный` | Тег стоит на коммите с ошибками. Почините, закоммитьте и поставьте тег на новый коммит. |
| `Apple не приняла сборку … INVALID` | Причина — в письме от Apple и в App Store Connect → TestFlight → сборка. |
| `Нет группы TestFlight «…»` | Имя в `TESTFLIGHT_GROUP` не совпадает с группой из шага 7. |
| Сборка висит в «Недостаточно данных об экспорте» (Missing Compliance) | В сборке уже указано, что шифрования нет, а задача «Раздача» подтверждает это ещё раз. Если всё же висит, нажмите на сборку → **Управление** → «Нет». |
| `Сборку не удалось отправить на проверку` | Не заполнена «Информация о тестировании» (шаг 7, п. 1). Заполните и перезапустите задачу «Раздача в TestFlight» (**Re-run failed jobs**). |
| Beta App Review отклонила сборку | Причина — в App Store Connect → TestFlight → сборка и в письме. Чаще всего это неработающая ссылка на политику конфиденциальности или неясно, как начать игру: ответьте проверяющему через App Store Connect, поправьте и отправьте снова. |
| `SDK version issue` | Сборка должна идти на Xcode 26+. Workflow использует `macos-26` и сам выбирает новейший Xcode 26. |
